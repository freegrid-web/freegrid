# Theming (CSS variables, dark theme) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every FreeGrid color, the font and the shadow come from `--fg-*` variables defined in one file, with a dark
theme (`fg-theme-dark`) and an automatic one (`fg-theme-auto`), and the default look unchanged.

**Architecture:** `src/css/variables.css` holds all variables (light defaults on `:where(:root)`, dark and auto
overrides); every other stylesheet only uses `var(--fg-…)`. A small TypeScript helper copies the grid's theme class
to the three elements FreeGrid appends to `<body>`. A computed-style snapshot taken before any change proves the light
theme is unchanged; a unit test bans color literals outside `variables.css`. The docs get a Theming page with a
playground and a variable table generated from `variables.css`.

**Tech Stack:** CSS custom properties, Vite/PostCSS (existing legacy-class plugin), TypeScript helper, Jasmine E2E via
Playwright, Vitest, VitePress (data loader + Vue component).

**Spec:** `docs/specs/2026-10-12-theming-design.md`

## Global Constraints

- Light theme (no theme class) renders exactly as today: same computed colors, fonts and shadows in Chromium,
  Firefox and WebKit. No size, padding, line-height or border-width changes.
- All theme values live in `packages/freegrid/src/css/variables.css`; no color literal anywhere else in FreeGrid's
  stylesheets (`transparent`, `inherit`, `currentColor` are allowed).
- Defaults on `:where(:root)`; themes: `.fg-theme-dark, [data-fg-theme="dark"]` and
  `.fg-theme-auto, [data-fg-theme="auto"]` (auto = dark values inside `@media (prefers-color-scheme: dark)`).
- Variable names: base `--fg-color-*`, `--fg-font-*`, `--fg-shadow`; component `--fg-<part>-<property>`.
- Legacy class names keep working (the CSS build already duplicates selectors).
- New TypeScript follows the project style (`export const name = (…): T => …`).
- One PR, squash merge. No `Co-Authored-By`. Check the build's exit code before trusting dist/E2E results.

## Review Focus

1. **A color that only appears in a state** (hover, active header, disabled menu item, invalid + selected, read-only
   in a dark theme) that the snapshot does not cover → visible change in light or unreadable in dark. Task 1's
   snapshot covers these states explicitly.
2. **Theme set on `<html>`/`<body>` vs on the grid vs `data-fg-theme`**: all three must give the same result,
   including floating elements. Task 4 tests the attribute form and an ancestor class.
3. **Grid destroyed or re-themed while a menu/date picker is open**: the floating element must pick up the current
   theme each time it opens, not only at creation. Task 4 opens the menu twice with a theme change in between.
4. **Pikaday CSS missing** (`freegrid.css`, not full): the date picker overrides must not break anything or add
   unexpected styles. Covered by the dist test in Task 3.
5. **User variables on an ancestor of the grid** reach the grid but not floating elements — documented in Task 5.

- [ ] **Step 2: `theme.ts`**

```ts
const THEMES = ['fg-theme-dark', 'fg-theme-auto'] as const;

export type ThemeClassName = typeof THEMES[number];

/**
 * The theme of the closest element (itself or an ancestor) with a `fg-theme-*` class or `data-fg-theme`.
 */
export const getThemeClassName = (element: Element | null): ThemeClassName | null => {
  for (let node = element; node; node = node.parentElement) {
    const byClass = THEMES.find(theme => node?.classList.contains(theme));

    if (byClass) {
      return byClass;
    }
    const byAttribute = node.getAttribute('data-fg-theme');

    if (byAttribute === 'dark' || byAttribute === 'auto') {
      return `fg-theme-${byAttribute}`;
    }
  }

  return null;
};

/**
 * Gives an element that FreeGrid appends to `<body>` (menus, comment editor, date picker) the grid's theme.
 */
export const applyTheme = (floating: Element, source: Element | null): void => {
  floating.classList.remove(...THEMES);
  const theme = getThemeClassName(source);

  if (theme) {
    floating.classList.add(theme);
  }
};
```
