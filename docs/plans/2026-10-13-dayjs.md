# Replace moment with Day.js — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** FreeGrid parses, formats and compares dates with Day.js (`dayjs` + `customParseFormat`) instead of moment,
with the same `dateFormat` / `timeFormat` token syntax and the same validation, editing and sorting behavior.

**Why Day.js** (agreed 2026-10-13): moment-compatible tokens (`DD/MM/YYYY`, `h:mm:ss a`), so users' settings keep
working; ~5 KB instead of ~70 KB; maintained. date-fns uses different tokens (`YYYY` is the week year there); `Intl`
cannot parse.

## Global Constraints

- Same behavior: every existing unit and E2E spec stays green in Chromium (baseline), Firefox and WebKit (known
  failures). Specs that use moment themselves to build expected values keep it (moment becomes a devDependency).
- Public changes, listed in the CHANGELOG and the docs: the plain UMD build needs `dayjs` and its
  `customParseFormat` plugin on the page instead of moment; `freegrid.full.js` exposes `window.dayjs` instead of
  `window.moment`; the ESM build imports `dayjs` instead of `moment`.
- Pikaday stays until FreeGrid's own date picker (next PR): it gets Day.js `parse`/`toString` functions, and its
  internal `require('moment')` is left unresolved so moment is not bundled.
- No `Co-Authored-By`. Check the build's exit code. One PR, squash merge.

## Review Focus

1. Lenient (non-strict) parsing differences: moment's forgiving `moment(value, format)` vs Day.js in date sorting
   and in the validator's "is a date at all" check.
2. Strict parsing with several formats (`timeValidator`'s list) and time-only formats.
3. Pikaday: the selected day, the input's text after picking, `correctFormat` re-formatting.
4. Bundles: no moment left in `freegrid.js`, `freegrid.full.js` or the ESM output.
5. Locale-dependent tokens (`MMM`, `MMMM`) still format in English by default.

## Task 1: Day.js in the code

- [ ] Add `dayjs` to dependencies; move `moment` to devDependencies (specs and the E2E page use it).
- [ ] `src/helpers/dayjs.ts`: one module that imports `dayjs` and `customParseFormat`, extends it once, and exports
  it (so every caller gets the plugin).
- [ ] Replace moment in `editors/dateEditor.js`, `validators/dateValidator.js`, `validators/timeValidator.js`,
  `plugins/columnSorting/sortFunction/date.js` with the same calls on Day.js (`dayjs(value, format, true).isValid()`,
  `.format()`, `.isSame/isBefore/isAfter`, `.toDate()`); Pikaday: `parse`/`toString` config functions and
  `setDate(…toDate(), true)` instead of `setMoment`.
- [ ] Build: `deps` = `['dayjs', 'numbro', 'pikaday']` (plus `dayjs/plugin/customParseFormat`), UMD globals
  `dayjs` / `dayjs_plugin_customParseFormat`, `commonjsOptions.ignore: ['moment']`; `full-entry.js` exposes
  `window.dayjs`; the E2E page loads moment (for specs) and dayjs + the plugin.
- [ ] Dist tests: no moment marker in any bundle; full UMD exposes `dayjs`; ESM imports `dayjs`.
- [ ] Unit + dist + all E2E specs that touch dates (`dateEditor`, `dateValidator`, `timeValidator`, `freegridDateSort`,
  `columnSorting`) in the three browsers; then commit.
